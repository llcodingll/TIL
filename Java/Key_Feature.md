## OOP


: object oriented programming

---
### 캡슐화(Encapsulation)
- 속성 == 변수
- 행위 == 메소드
- `캡슐 == 클래스`

외부 코드가 데이터에 직접 접근하지 못하도록 하는 방어막 역할

e.g.) 캡슐알약 - 안에 있는 약은 보고하고 캡슐로 방어막을 침

내부에서는 `private`, 외부에서는 `public` 메소드를 노출해 정보 은닉 가능
=> 느슨한 결합
#### Getter/Setter

---

### 추상화(Abstraction)
복잡한 시스템 -> 핵심 개념/기능을 간추려내는 것
- 수행 방법이 아닌 수행 일에 집중

e.g.) 핸드폰 - 핸드폰 내부의 시스템적 로직을 사용자가 알아야하는 것이 X, 앱을 누르면 앱이 실행된다를 알면 작동시킬 수 있음

---

### 상속(Inheritance)
한 객체를 또 다른 객체가 이어받는 것

e.g.) 자동차 - A라는 이름의 자동차의 좋은 엔진을 B라는 디자인이 다른 자동자에 동일하게 이용할 수 있음

---

### 다형성(Polymorphism)
- Overloading: 이름은 같지만 파라미터가 다른 메소드
- Overriding: 상속을 받아 메소드 재정의
---
### 접근 제어자(Access Modifier)
1. public: 어디서나 접근 가능
2. private: `클래스`내에서만 접근 가능
3. protected: `상속 받은 클래스`이거나 `동일 패키지`내에서만 접근 가능
4. default: 접근 제어자를 부여하지 않은 경우의 기본, `동일 패키지`내에서만 접근 가능
