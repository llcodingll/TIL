## DB Modeling
개념적 → 논리적 → 물리적 모델링

### 개념적 데이터베이스 모델링(ERD)
- 사용자 부문의 처리 현상 분석
- 중요 실체와 관계를 파악해 ERD 작성
- 실체에 대한 상세 정의
- 식별자 정의, 식별자 업무 규칙 정하기
- 실체별로 속성 상세화
- 필요한 속성 / 영역 상세 정의
- 속성에 대한 업무 규칙 정의
- 사용자와 함께 모델 검토
⇒ 기호가 정해져 있음
---
### Entity


: 사용자와 관계가 있는 주요 객체(데이터로 관리되어야 하는 것)

- 찾는 법!
    - 영속적으로 존재
    - 새로 식별 가능한 데이터 요소
    - Attribute를 가진 거
---
### Attribute


: 저장할 필요가 있는 실체에 관한 정보
- 기초 속성 e.g.) 급여 —가공—> 추출 속성
- e.g.) 연봉  → 설계 속성
---
### Key
- 식별자: 1 Entity 내에서 인스턴스를 구분할 수 있는 단일 속성/속성 그룹
- Candidate Key: Entity 내에서 각각 인스턴스를 구분할 수 있는 속성(기본키 될 수 있음)
- Primary Key: Entity에서 각 인스턴스를 유일하게 식별하는데 적합한 Key
- Alternate Key: 후보키 중에서 기본키로 선정되지 않은 Key
- Composite Key: 하나의 속성으로 기본키가 될 수 없는 경우, 둘 이상의 컬럼을 묶어서 식별자로 정의
- Surrogate Key: 식별자가 너무 길거나 여러 개의 속성으로 구성된 경우, 인위적으로 추가

## ERD 작성
### 개념적 데이터베이스 모델링
- Relationship: 두 Entity 간의 업무적 연관성/관련 사실
- 각 Entity 간의 특정한 존재 여부 결정
- 현재 관계 + 나중에 사용될 경우 고려
#### 차수 종류
- `1:1`: 두 실체의 record가 하나씩
- `1:N`: 부모 실체의 1 record가 자식 실체의 여러 record
- `N:M`: 양쪽 실체 간의 여러 record

### 논리적 데이터베이스 모델링


: 개념적 데이터베이스 모델링 단계에서 정의된 ERD를 Mapping Rule 적용해 관계형 DB 기반 Schema 설계 + 정규화
#### Mapping Rule
- Entity = Table
- Attribute = Column
- 식별자 = PK
- 관계 = FK, Table
#### 정규화


: 중복을 최소화 + 데이터 구조화 하는 프로세스
- 목적
  - DB 변경 시 이상 현상 제거
  - DB 구조 확장 시 다시 디자인하는 경우 최소화
  - 사용자에게 데이터 모델을 의미있게 작성하도록 함
- `1차 정규화(Atomic Columns`
  - 하나에 한 개의 값만
- `2차 정규화(부분 함수 종속 제거`
  - 관련있는 거끼리 묶어서 table 분리
- `3차 정규화(이행적 함수 종속 제거`
  - A가 B이고, B가 C이면, A는 C이다

### 물리적 데이터베이스 모델링


: 논리적 DB 모델링 단계에서 얻어진 DB Schema를 좀 더 효율적으로 구현하기 위한 작업
- DBMS 특성에 맞게 실제 DB내의 개체들 정의
  - Column의 domain 설정(int, varchar, date, ...)
- 데이터 사용량 분석과 업무 프로세스 분석을 통해 보다 효율적인 DB가 될 수 있게 효과적 index 정의, 상황에 따른 역정규화
  - Index, Trigger, 역정규화
#### Denomalization(역정규화)
- 시스템 성능 고려, 기존 설계 재구성
- 정규화 위배 행위
- table 재구성
- 방법
  - 데이터 중복(컬럼 역정규화)
  - 파생 컬럼 생성
  - 테이블 분리
  - 요약 테이블 생성
  - 테이블 통합
